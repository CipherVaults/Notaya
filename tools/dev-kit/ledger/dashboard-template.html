🧮 How the forecast is built

  1. Supply. The input assumes windows per week and % already used. Reset dates and banked resets come from the CSV inputs. Example figures are invented.
  2. Work. Each version has a size in plan points (small = 1, medium = 3, large = 6, extra large = 12) from the version plan. Points × extra work ÷ points per window = windows needed.
  3. Claude's share. Directing, inspecting every diff, merging and records draw from Claude's own weekly limit, using the configured cap. If Claude's allowance is empty, Codex waits, even if Codex has plenty left.
  4. The calendar. Day by day the model spends what both allowances and the daily window cap allow, adds a pause after each version, and records when each version finishes. Banked resets are used when the weekly allowance is empty and the next weekly reset is over a day away.
  5. Who pays. Primary allowance and optional secondary builder capacity are model inputs. The model simulates banked resets; it never applies them to an account.
