🧮 How the forecast is built

  1. Supply. Codex's week holds about full 5-hour windows measured. Ahmed has used % of this week. His week resets on 2026-11-14 at 15:44 UTC and every 7 days after. Ahmed has two banked resets; each refills the whole week and the 5-hour window, and is used only after the week is fully spent (Ahmed, 08:57 UTC).
  2. Work. Each version has a size in plan points (small = 1, medium = 3, large = 6, extra large = 12) from the version plan. Points × extra work ÷ points per window = windows needed.
  3. Claude's share. Directing, inspecting every diff, merging and records draw from Claude's own weekly limit, which Ahmed capped at 70%. If Claude's allowance is empty, Codex waits, even if Codex has plenty left.
  4. The calendar. Day by day the model spends what both allowances and the daily window cap allow, adds a pause after each version, and records when each version finishes. Banked resets are used when the weekly allowance is empty and the next weekly reset is over a day away.
  5. Who pays. Versions finished while Ahmed's own allowance lasts (this week, the Nov 14 reset and the two banked resets) are marked Ahmed's quota. After that point the work runs on Ahmed's weekly Codex allowance only (about one version every 4 to 5 days). Mohamed has no Codex, only a Claude Pro subscription; if he builds with it, the slider adds what his Claude week can build (a guess).
