## 3. Decisions Claude took (for the owner to confirm)

- "Home pages" read as the Home view (banner, favorites, recent pages, notebooks) plus covers and icons, not as a per-notebook landing page.
- Free-position pictures work in the page body only (not inside columns, lists or tables, where they stay in the text flow). Alt+drop was dropped because Alt is unreliable in WebView2.

## 4. Security

- **Recent searches are a security-behavior addition** (a search term can reveal what a note says): the last five (each at most 200 characters), stored in the encrypted settings record, wiped from memory at lock, readable by the UI only through four commands, not through `get_settings`; `save_settings` cannot overwrite them; stored only when a result is opened; "Clear recent searches" and X remove them. Written in `docs/security-design.md` (limitations). The owner should confirm he wants this.
- **2 GB limits:** limits remain bounded (2 GB per file, 4 GB total, 2 GB of pictures/text per import); the Zip-bomb ratio limit (100) is unchanged. Memory use of a 2 GB import was not measured.
- **Covers and icons** (`set_page_look`): only `gradient:<name>`, `solid:#rrggbb` or a picture already in the vault (PNG/JPEG/GIF/WebP), never an outside address; icon pictures at most 2 MB; vault cleanup counts an icon picture as in use. Unit tested.
- **Mermaid:** strict mode, no HTML labels, `%%{init}%%` directives and front matter stripped, the drawing is cleaned again (no script, iframe, img, event attributes, outside addresses, `<a>` links) and added with DOM calls; 50,000-character and 500-edge limits, 15-second wait. The Content-Security-Policy is unchanged; the bundle has no `eval`. Tested with a hostile-source set in a mock with the CSP applied as a meta tag.
- **New third-party code:** `mermaid` 12.2.0 and its 116 packages (installed for it). `npm audit`: 0. **`elkjs` 0.9.3 is EPL-2.0** (file-level copyleft, shipped unmodified): recorded in `THIRD-PARTY-NOTICES.md` (open decision 15); copyright lines and license texts of the Mermaid packages are not yet copied into that file.

**Found later in the PC round (reported ~23:35 UTC, PC clock): BUG-9, Mermaid does not draw in the real exe.** All nine sample diagrams show "Cannot assign to read only property 'valueOf' of object '#<g>'". Cause: `src-tauri/tauri.conf.json` has `"freezePrototype": true`, so Tauri freezes `Object.prototype` in every frame of the real app (also in iframes); libraries inside Mermaid (for example the dayjs duration plugin: `valueOf` assigned on a class prototype) assign such properties and throw in strict mode. Reproduced in the cloud by freezing `Object.prototype` in the browser mock; the earlier mock checks did not apply that setting, which is why they passed (lesson: the Mermaid mock check must run with the freeze on). Options put to the owner (security-behavior change, so his call): (1) turn the freeze off, document it in the security design, keep Mermaid; (2) keep the freeze and ship V1.5.1 without Mermaid; (3) keep the freeze and patch the libraries at build time (fragile). **Decided by the owner (2026-11-04 23:20:04 UTC): option 1, the freeze is off** (section 8c).
