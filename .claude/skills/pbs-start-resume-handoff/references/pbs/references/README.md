## Historical wording and modern candidate guidance

Read these boundaries before applying the historical guide. Preserving a source does not make every example a universal rule or current permission.

| Source wording or feature | What it establishes | Modern candidate boundary |
| --- | --- | --- |
| Current Position says a future thread should be able to resume from that section “alone” | Strong context recovery and a practical endpoint are intended | Context is not execution authority. Reconcile current authorization, live owners, and applicable evidence before acting; a historical session does not resume paused work. The supplied guide's opening Authority boundary already makes this distinction. |
| Time offers optional approximate Total Working Hours | The original form allowed a rough effort summary | Do not infer active work from elapsed time or gaps. The candidate uses measured work blocks and exclusions, or “Not measured.” Retain any existing historical estimate as attributed and approximate rather than silently turning it into measured time. |
| Decisions are described as settled unless reopened; examples include “likely” platform choices | The source distinguishes decisions, including provisional and deferred labels | Identify the actual decision owner, status, scope, and evidence. A likely option, recommendation, implementation, or silence is not confirmed approval. |
| An example says no Failure Intelligence entry is needed because an issue was caught during design | That example reached a local conclusion about one design issue | Consequential near-misses can warrant a separate incident/control record even before implementation. Assess significance and recurrence; do not use design-stage timing as a universal exclusion. |
| Next Steps gives an example of rewriting the full project log after format approval | A particular historical workflow contemplated a later rewrite | A format example grants no general rewrite authority. Routine maintenance updates affected owners proportionately; any historical reconstruction needs its own scope, recoverable baseline, and preservation checks. |
| Examples choose capture/analysis tools, roles, and sequencing | Concrete examples teach the method | They are illustrative, not mandatory application choices, actual current project facts, or permission to create accounts, send data, or change a project. |
| Confidence reflects stability of project direction | The source asks for a reasoned confidence assessment | Tie confidence to a specific claim or area and its evidence limits. Stable direction does not establish technical correctness, publication, or owner acceptance. |
| Actions use bullets and defer deeper meaning to Insights/Decisions | The source separates event sequence from meaning | Keep that distinction while allowing H5 work blocks and enough local rationale to understand a consequential chronology. Avoid mechanical logs and repeated paragraphs. |
| Optional Codex Work Performed and Personal Note | The source recognizes execution attribution and human meaning | Keep roles accurate, remove unused optional sections, and preserve only expressed or grounded human reflections. Do not invent executor participation, independent review, identity, or feelings. |
| Explanatory H2 headings, original H3 skeleton, and separate multi-project wrapper | Several deliberate forms coexist in the supplied source material | Name the selected profile. Do not present the H1/H2 portable derivative or H4 multi-project core as the sole exact original hierarchy. |

The complete historical explanations remain useful. The candidate's safeguards clarify where a returning reader needs stronger evidence or an explicit current decision. They do not erase the historical wording or retroactively change what earlier sessions believed.
